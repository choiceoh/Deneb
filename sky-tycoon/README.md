# Sky Tycoon — 항공사 경영 시뮬레이션

코에이의 **에어매니지먼트 II** 계보를 잇는 턴제 항공사 경영 시뮬레이션.
세계 40개 도시를 무대로 슬롯을 확보하고, 노선을 열고, 기재를 갈아 끼우며
시나리오가 끝날 때 기업가치 1위에 오르거나 경쟁사를 전부 삼키는 것이 목표다
(시대에 따라 20년 · 16년 · 17년).

**Kotlin Multiplatform + Compose Multiplatform.** 화면 한 벌로 안드로이드와 데스크톱이 함께 돌아간다.
기준 화면은 **안드로이드 폰 세로**이고, 넓은 화면에서는 사이드 레일 + 2단 레이아웃으로 펼쳐진다.

## 모듈

| 모듈 | 내용 |
|---|---|
| `core` | 시뮬레이션 전부 (순수 Kotlin, UI 의존 없음). 수요·시장점유·원가·AI·이벤트·주식 |
| `app` | Compose Multiplatform 공용 UI + 데스크톱 실행 엔트리 |
| `android` | 안드로이드 껍데기 (Activity 하나). **Android SDK 가 있을 때만 빌드에 포함된다** |

`settings.gradle.kts` 가 `ANDROID_HOME` / `local.properties` 를 보고 SDK 유무를 판단한다.
SDK 가 없는 환경(CI 컨테이너 등)에서도 `core` 와 `app`(데스크톱)은 그대로 빌드·테스트된다.

## 실행

```bash
./gradlew :app:run          # 데스크톱 창으로 플레이
./gradlew :core:jvmTest     # 시뮬레이션 테스트 (밸런스·규칙·20년 완주)
./gradlew :app:screenshots  # X 서버 없이 주요 화면을 PNG 로 렌더 → app/build/screenshots
```

안드로이드 (SDK 가 설치된 머신에서):

```bash
./gradlew :android:assembleDebug     # APK
./gradlew :android:installDebug      # 연결된 기기에 설치
```

## 게임 규칙 요약

**턴 = 1분기.** 시나리오는 제트 여명기(1970~), 메가캐리어 전쟁(1990~), 현대의 하늘(2012~).

- **슬롯** — 공항마다 주간 슬롯 총량이 정해져 있고 모든 항공사가 나눠 갖는다.
  주간 왕복 1회에 양쪽 공항 슬롯이 하나씩 필요하다. 허브가 포화되면 확장이 막히므로,
  그때부터는 **더 큰 기재로 갈아타는 것**이 유일한 성장 수단이 된다.
- **수요** — 도시쌍마다 경제 규모(출장)와 관광 매력(레저)에서 수요가 나온다.
  두 세그먼트는 성격이 다르다. 출장객은 운임에 둔감하고 편수·서비스를 보고,
  관광객은 정반대다. 그래서 운임 전략이 곧 손님의 종류를 고른다.
- **시장 점유** — 같은 구간의 항공사들이 다항 로짓으로 승객을 나눠 갖는다.
  운임·편수·서비스·브랜드·허브 지배력·안전 신뢰도가 효용에 들어간다.
  좌석이 모자라 넘친 수요는 여유 있는 경쟁사로 흘러간다.
- **경쟁사 AI** — 플레이어와 **똑같은 명령 계층**(`Actions`)만 사용한다.
  AI 가 규칙을 우회하는 일이 구조적으로 불가능하다.
- **인수합병** — 지분 50%를 넘기면 회사를 통째로 삼킨다. 한 분기 매입 상한은 10%,
  지분이 쌓일수록 매집 단가가 오르고, 당하는 쪽은 **유상증자로 희석**해 방어할 수 있다.
  매입 상한과 증자 한도는 모두 **분기 누적**으로 잰다 (한 분기에 나눠 사서 우회할 수 없다).
- **부대사업** — 슬롯만 사둔 도시가 아니라 **취항 중인 노선이 있는 도시**에만 낼 수 있다.
  정비창은 전사에 하나만 두면 되고(할인이 회사 단위로 적용된다) 두 번째는 아예 막힌다.
- **역사 이벤트** — 두 차례 오일쇼크, 미국 규제완화, 플라자 합의, 걸프전, 아시아 외환위기,
  9·11, 화산 폭발, 올림픽 특수까지 연도에 맞춰 터진다.

## 밸런스를 만질 때

수치는 전부 `core/src/commonMain/kotlin/skytycoon/core/sim/Balance.kt` 한 파일에 모여 있다.
`core/src/commonTest` 의 `BalanceTest` 가 기준 노선의 수지를 지켜본다:

- 독점 노선은 마진 12~55% (확장할 맛이 나야 한다)
- 3사 경쟁이 붙으면 마진이 확실히 깎이고 탑승률이 떨어진다
- 경쟁 시장에서 운임을 올리면 승객을 뺏긴다

`DiagnosticTest` 는 `@Ignore` 로 꺼 두었다. 분기별 손익 흐름을 눈으로 보고 싶을 때만 켠다.

### 화폐 단위 주의

운임·원가 상수는 **시나리오 시작 시점의 명목 달러**다. `World.inflation` 이 해마다 함께 밀어 올린다.
반면 기재 카탈로그 가격은 이미 시대별 명목가(747-100 = 4,500만 달러)라 물가를 곱하지 않는다.
새 상수를 추가할 때 이 구분을 지키지 않으면 시나리오마다 수지가 어긋난다.

### 수요 스케일

실제 서울–도쿄는 연 수백만 명이 오가지만 그대로 쓰면 여객기 한 대(주 14왕복 = 분기 5만 4천 석)가
시장에 아무 흔적도 남기지 못해 운임도 경쟁도 무의미해진다. 그래서 수요를 게임 스케일로 압축했다 —
간선 노선 하나가 항공사 두세 곳을 먹여 살리는 정도. 승객 1명은 현실의 여러 명에 해당하는 추상 단위다.

## 세이브

`GameState` 전체가 `kotlinx.serialization` 으로 직렬화되는 순수 데이터라 JSON 한 덩어리가 곧 세이브다.
난수도 상태(`rngState`)가 세이브에 실리므로 같은 시드는 같은 전개를 재현한다.

**분기를 넘길 때마다 자동 저장된다.** 안드로이드는 백그라운드에서 프로세스가 통째로 정리될 수 있어서,
저장이 없으면 20년짜리 캠페인이 소리 없이 사라진다. 시작 화면의 "이어서 하기"와
재무 화면의 저장/되돌리기가 같은 슬롯을 쓴다.

저장 위치는 진입점이 정한다 (`SaveStorage.current`) — 데스크톱은 `~/.skytycoon/save.json`,
안드로이드는 앱 전용 저장소. 테스트에서는 메모리 구현으로 갈아 끼운다.

## CI

`.github/workflows/sky-tycoon.yml` 이 `sky-tycoon/**` 변경 시 `:core:jvmTest` 와
`:app:compileKotlinDesktop` 을 돌리고, 렌더한 화면 PNG 를 아티팩트로 올린다.
독립 Gradle 빌드라 루트의 다른 게이트에는 걸리지 않으므로 이 레인이 유일한 자동 검증이다.
