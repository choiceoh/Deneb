# 로컬 엔진 실행 통계

엔진 화면은 기존 가동·우회·일별 통계에 최근 30분과 24시간 실행 통계를 더한다.
게이트웨이의 기존 15초 스크레이프를 재사용하며, 앱 화면이 활성화되어 있을 때
15초마다 다시 읽는다. 별도 벤치마크나 GPU 프로파일러를 실행하지 않는다.

## 지표의 의미

| 항목 | 집계 기준 |
| --- | --- |
| 호스트 디코드 회차 | 디코드 호스트 호출 횟수 / 해당 호출 시간 합계 |
| 완료 스텝당 출력 | 조건별 완료 출력 토큰 합계 / 완료 스텝 수 |
| 요청 디코드 | TPOT 표본 수 / TPOT 시간 합계 |
| 드래프트 수용률 | 수용 토큰 합계 / 제안 토큰 합계 |
| 구간 합산 처리량 | 구간 생성 토큰 / 유효 관측 벽시계 시간 |
| 실제 프리필 | 실제 계산한 청크 토큰 / 프리필 호스트 실행 구간 |
| 단계별 비용 | 기존 샘플링 계측의 단계별 기기 시간 / 표본 스텝 수 |
| 첫 토큰·대기·전체 응답 P50/P95 | 구간별 누적 히스토그램 버킷 차분으로 추정 |
| 추론·답변 길이 | 완료된 채팅 선택지의 추론 및 본문 토큰, 평균과 P50/P95 |
| 토큰 제한 종료 | finish reason이 length인 완료 선택지 비율 |

스텝과 호스트 호출은 항상 같지 않다. 기기 버스트는 한 번의 호출 안에서 여러
스텝을 실행한다. 조건표는 완료한 실제 버스트 반복 수를 사용하고, 상단의 호스트
디코드 회차는 기존 호스트 호출 계측을 그대로 명시한다. 두 수치를 섞어 속도 향상을
판정하지 않는다.

조건표는 실제 동시성, 시작 시점의 최대 문맥 길이, 캐시 재사용, 측정 방식을 함께
수집한 행이다. 독립 분포를 곱해 가상의 C=4/128K 표본을 만들지 않는다. 동기 시간,
비동기 완료까지의 체류 시간, 기기 버스트 시간을 구별한다. 비동기 체류 시간은 서로
겹칠 수 있다. 종료된 ghost 행이 섞인 그래프는 조건 비교에서 제외한다.

기존 일별 프리필은 캐시 효과가 포함되는 체감 수치로 표시한다. 새 실제 프리필
카운터가 없는 이전 엔진에서는 새 항목을 측정 없음으로 표시한다. 요청별 캐시 상태는
이번 요청이 재사용한 토큰 유무이며, 캐시 hit ratio의 다른 정의를 대신하지 않는다.

## 비교와 결측

요약은 현재 모델·빌드·부팅·K·드래프트 정밀도의 실행만 집계한다. 이전 실행은
추이와 이벤트에 남긴다. 빌드 정보가 없으면 미제공으로 표시한다. Git revision만으로
dirty build의 파일 내용까지 인증하는 것은 아니다.

관측 공백, 카운터 리셋, 재시작을 가로질러 차분하지 않는다. 수집 실패는 0 tok/s로
기록하지 않고 그래프에 빈 구간으로 남긴다. 분자나 분모가 없으면 측정 없음이며,
실제로 관측한 0%는 유지한다. 히스토그램의 최상위 무한 버킷에 들어가는 분위수는
유한값을 만들어내지 않는다. P95를 일별 평균의 P95로 계산하지 않는다.

시계열은 24시간, 최대 12,000개 구간으로 제한한다. 한 스크레이프의 진단 시리즈가
2,048개를 넘으면 일부만 합산하지 않고 그 표본을 제외한다. 저장 파일에는 요청
본문·토큰 ID·요청 식별자가 들어가지 않는다. 저장은 기존 5분 flush 주기를 사용하므로
비정상 종료 시 최근 미저장 구간은 유실될 수 있다.

추이의 세로선은 실행/수집 변경이며 음영은 기존 라우터의 클라우드 우회 구간이다.
45초 이상 새 표본이 없거나 실행 식별이 달라지면 수집 지연을 표시한다. RPC 갱신이
실패하면 이전 데이터라는 안내를 유지한다. 단계별 겹치는 시간을 전체 지연으로
합산하지 않으며, 단계 계측이 비활성화되어 표본이 없으면 측정 없음으로 표시한다.

## 구현 진입점

- 스크레이프: `gateway-go/internal/core/observe/engine_diagnostics.go`
- 구간 저장: `gateway-go/internal/ai/enginespeed/diagnostics.go`
- RPC 및 계산: `gateway-go/internal/runtime/rpc/handler/handlerminiapp/engine_diagnostics.go`
- 화면: `client-android/app/composeApp/src/commonMain/kotlin/ai/deneb/deneb/DenebEngineDiagnostics.kt`
- 연결 검증: `scripts/dev/engine-statistics-smoke.py`
- ST 측 계측: 별도 stkernel 저장소의 DiagnosticMetrics 클래스

Go wire 구조체가 계약의 원본이며 Kotlin과 TypeScript 양쪽 생성기를 실행한다.
새 조건·프리필·응답 길이는 ST 계측과 게이트웨이/앱이 함께 배포된 뒤 채워진다.
기존 엔진도 제공 중인 히스토그램과 카운터는 계속 표시할 수 있다.

## 검증

```sh
python3 scripts/dev/engine-statistics-smoke.py --output /tmp/engine-statistics.json
scripts/dev/ui-inspect.sh engine_statistics "click:24시간;click:30분"
make ci
```

smoke는 매 실행마다 별도 인스턴스와 loopback fixture를 만들고 종료 시 정리한다.
`--hold-seconds 600`은 실제 네이티브 앱에서 검토할 시간을 제공한다. 이 fixture의
속도는 계산 계약 검증용 가상 수치이며 실제 모델 성능 증거로 사용할 수 없다.
