# 0006. 스킬 절차 수행의 증거는 도구 호출만이 아니다

**Status:** accepted

## Context

진화 수용이 30일간 0건이었고, 원인은 검증 코퍼스의 98%가 합성이라는 것이었다
(#4801/#4803/#4804). 실사용 케이스를 만드는 유일한 입구는 `exercised=no` —
"절차가 주입됐는데 선언된 도구가 한 번도 실행되지 않았다" — 인데, 이 판정은
`exercise_tools`(없으면 `requires_tools`) 선언에만 의존한다.

2026-08-26 스킬 31개를 전수 판독했다. 계측된 건 11개고, 남은 20개를 **절차 기준으로**
하나씩 판정하니 정직하게 도구를 선언할 수 있는 건 `retrieval-plan` 하나뿐이었다(#4806).
본문에 도구 이름이 나온다고 선언하면 안 된다 — `weekly-report`는 폴백 경로에 "이때도
도구를 새로 호출하지 마라"라고 적혀 있어 **도구 0회가 정상**이고, `email-analysis`는
도구 절을 "의무 단계가 아니라"로 못박았으며, `contract-review`의 `mail_archive`는
"메일 첨부면" 조건부다. 이런 걸 선언하면 정상 실행이 실패로 기록돼 코퍼스를 **반대
방향으로** 오염시킨다.

남는 부류가 문제다. `deneb-ui-authoring`·`decision-premortem`·`skill-factory`·
`proactive-gate`는 **추론·저작형**이다. 절차가 요구하는 건 도구 호출이 아니라 답변의
모양이다 — 카드를 emit 했는가, 반증을 거쳤는가, SKILL.md를 산출했는가. 이들은 도구로는
원리적으로 계측 불가라 영원히 `unknown`이고, 따라서 **모델이 절차를 조용히 무시해도
아무 신호가 남지 않는다.** 지시를 무시하기 가장 쉬운 스킬이 정확히 계측 사각에 있다.

## Decision

**`Exercised`의 정의를 "선언된 도구가 돌았다"에서 "선언된 증거가 관측됐다"로 넓힌다.**
도구 호출은 증거의 한 종류일 뿐이다.

- 새 frontmatter 필드 `exercise_output` — 답변에서 관측될 **결정적** 패턴 목록.
  기존 `exercise_tools`와 **동렬**이며 둘의 합집합에 대해 **any-of**로 판정한다.
- 패턴 문법은 오탐을 막기 위해 의도적으로 좁게 셋만 둔다:
  - `fence:<lang>` — 해당 info string을 가진 코드펜스 (예: `fence:deneb-ui`)
  - `heading:<text>` — 정규화 일치하는 마크다운 헤딩
  - 그 외 — 정규화 부분문자열
  정규화는 검증 채점기와 **같은 함수**(`normalizedValidationText`)를 쓴다. 새 정규화
  규칙을 만들지 않는다.
- 판정 대상은 `AgentResult.DeliverableText` — 진행 내레이션을 뺀 실제 산출물. `AllText`를
  쓰면 "이제 카드로 정리할게요" 같은 예고가 증거로 오인된다.
- **활성화는 절대 게이팅하지 않는다.** `requires_tools`의 교훈 그대로 — 계측하려다
  스킬이 사라지면 안 된다.
- `SkillUseAttribution`에 `EvidenceKind`(`tools`/`output`/`none`)를 실어 **어떤 증거로**
  판정했는지를 원장에 남긴다.
- **섀도 우선**: 출력 증거만으로 판정된 `exercised=no`는 `DENEB_SKILL_OUTPUT_EVIDENCE=1`
  이 무장될 때까지 **검증 케이스를 만들지 않는다**. 원장·헬스에는 그대로 기록돼
  오탐률을 먼저 관측할 수 있다. 오늘 배운 것 — 잘못된 선언은 코퍼스를 반대로 오염시킨다 —
  을 코드로 강제하는 안전판이다.
- 아무 증거도 선언하지 않은 스킬은 그대로 `unknown`이다. **미측정과 실패를 섞지 않는다.**

## Alternatives rejected

- **LLM 심판이 답변을 채점**: 한국어 산문을 유연하게 볼 수 있지만 턴마다 비용이 들고
  비결정적이다. 수용 게이트 1순위는 결정적 replay라는 기존 결정이 있고, "LLM 채점뿐"인
  설계는 이미 한 번 기각됐다. 결정적 증거로 못 잡는 것이 남으면 **그때** 보조로 검토한다.
- **스킬 본문에서 완료 조건을 자동 추출**: 저작 부담이 0이라 매력적이지만 추출이
  휴리스틱이고, 잘못 뽑으면 정상 답변을 실패로 적는다. 오탐 비용이 미계측 비용보다
  크다 — 오늘 도구 선언에서 얻은 결론과 같다.
- **도구 미선언 스킬을 일괄 `exercised=no` 처리**: 계측 커버리지는 즉시 100%가 되지만
  전부 거짓 실패다. 코퍼스를 굶기는 것보다 나쁘다.
- **`requires_tools` 재사용**: 활성화 게이트라서 계측하려다 스킬을 죽인다. 이미 기각된
  경로다(`exercise_tools`가 별도 필드로 존재하는 이유).

## Consequences

- 추론·저작형 스킬도 계측 가능해진다. 첫 적용은 `deneb-ui-authoring`(`fence:deneb-ui`) —
  절차가 요구하는 산출물이 카드 그 자체라 오탐 여지가 가장 작다.
- **첫 적용은 규칙의 경계에 있다.** `deneb-ui-authoring`의 Output Contract는 "짧은 답·
  잡담·진행 내레이션은 산문으로"라는 예외를 두므로 카드는 엄밀히 **조건부**다. 트리거가
  "카드로"·"표로 보여" 같은 명시 요청이라 실제 발화 시점엔 사실상 무조건이지만, 그
  간극이 정확히 섀도 모드가 재려는 값이다 — 이 파일럿의 목적은 계측 개시가 아니라
  **오탐률 관측**이다. 관측 없이 무장하지 말 것.
- 지켜야 할 것: **패턴은 무조건적인 것만 선언한다.** 조건부 산출물(“필요하면 카드로”)에
  패턴을 걸면 정상 실행이 실패로 적힌다. 선언 전에 스킬 본문이 그 산출을 *의무*로
  두는지 확인할 것 — 도구 선언과 같은 규칙이다.
- 섀도 해제(`DENEB_SKILL_OUTPUT_EVIDENCE=1`)는 원장에서 출력 증거 판정의 오탐률을
  확인한 뒤에 한다. 무장 전까지 코퍼스는 영향받지 않는다.
- `EvidenceKind`가 원장에 남으므로, 나중에 "출력 증거로 잡은 실패가 진짜였나"를
  사후 검증할 수 있다.
